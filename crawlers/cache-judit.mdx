---
title: "Consulta Cache Judit"
description: "Essa consulta funciona da seguinte forma, retorna de forma sincrona o que temos na nossa base de dados e em paralelo cria uma request normal que vai consultar os tribunais,"
icon: "shield"
---


Na resposta sincrona, retornamos apenas dados que já estão em nossa base de dados, com isso ela gera uma resposta mais rapida porém pode haver um delay na completude das informações. É importante consultar a resposta da request criada que vai nos tribunais trazer a informação completa e atualizada.

<Steps>
 <Step title="Payload" stepNumber="1">
   Para realizar a consulta de forma sincrona, é necessário primeiramente criar uma requisição para o endpoint.

   ```bash
 curl --request POST \
  --url https://lawsuits.prod.judit.io/requests/create \
  --header 'Content-Type: application/json' \
  --header 'api-key: <api-key>' \
  --data '{
	"search": {
		"search_type": "cpf",
		"search_key": "999.999.999-99",
		"search_params": {
			"pagination": {
				"page": 1,
				"page_size": 50
			}
		}
	}
}'
    ```

Essa consulta é comumente utilizada quando se tem a necessidade por um tempo de resposta baixa, como em rotinas de onboarding.

## Exemplo de payload:

```json 
{
	"search": {
		"search_type": "cpf",
		"search_key": "092.065.297-22"
	}
}
```

## Resposta esperada:

```json 
{
	"has_lawsuits": true,
	"request_id": "bd2be78e-2d04-4fad-ad85-b6058e7cc4f4",
	"response_data": []
}
```

Lembrando que com o request_id você pode consultar a resposta vinda dos tribunais da mesma forma que é feito na criação de requests padrão: https://docs.judit.io/api-reference/endpoint/requests/create
