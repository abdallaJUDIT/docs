**Official Justice Gazette Monitoring** scans the Electronic Justice Gazette (DJE) daily for publications containing the registered term. The search is performed across **all text fields** of the publication — parties, lawyers, court organ, full text — regardless of the `search_type` chosen.

> 🤖 Endpoint: `POST https://tracking.production.judit.io/tracking` with `response_type: "communication"`. With each new DJE edition, Judit processes the publications and delivers via webhook those that match your term.

## When to use

<CardGroup cols={2}>
  <Card title="Intimation tracking" icon="bell">
    Get notified immediately when a CPF, CNPJ or OAB is mentioned in an intimation or publication in the DJE.
  </Card>
  <Card title="Name or term watch" icon="magnifying-glass-dollar">
    Monitor any word or expression — a company name, a court, a judge — and receive all matching publications.
  </Card>
  <Card title="Compliance & due diligence" icon="shield-halved">
    Ensure no relevant publication about a client, supplier or counterpart goes unnoticed.
  </Card>
  <Card title="Law firms" icon="user-tie">
    Centralize the publication tracking for all clients in a single webhook stream.
  </Card>
</CardGroup>

<Steps>
  <Step title="Creating the tracking" stepNumber="1">
    ## Request payload

    The POST request must include a payload with the following properties:

    - `recurrence`: Execution frequency in days. For DJE monitoring, we recommend `1` (daily), since the gazette is updated every day with new publications;
    - `search_type`: Defines the type of search. Accepted values are: `cpf`, `cnpj`, `oab` or `name`. **Regardless of the type chosen, the search is performed across all text fields of the publication**;
    - `search_key`: The term to search for — CPF, CNPJ, OAB number or any free name/expression;
    - `response_type`: Must be `"communication"` to activate DJE monitoring;
    - `notification_emails` (optional): Array of email addresses that will receive notifications for every tracking update.

    <Note>
      This tracking type **does not accept additional filters** (`filter`, `side`, `tribunals`, etc.). Matching is done by full-text search across the entire publication.
    </Note>

    <CodeGroup>

    ```bash cURL (Name / Any Term)
    curl --location 'https://tracking.production.judit.io/tracking' \
    --header 'api-key: <API-KEY>' \
    --header 'Content-Type: application/json' \
    --data '{
        "recurrence": 1,
        "search": {
            "search_type": "name",
            "search_key": "EXAMPLE NAME",
            "response_type": "communication"
        }
    }'
    ```

    ```bash cURL (CPF)
    curl --location 'https://tracking.production.judit.io/tracking' \
    --header 'api-key: <API-KEY>' \
    --header 'Content-Type: application/json' \
    --data '{
        "recurrence": 1,
        "search": {
            "search_type": "cpf",
            "search_key": "999.999.999-99",
            "response_type": "communication"
        }
    }'
    ```

    ```bash cURL (CNPJ)
    curl --location 'https://tracking.production.judit.io/tracking' \
    --header 'api-key: <API-KEY>' \
    --header 'Content-Type: application/json' \
    --data '{
        "recurrence": 1,
        "search": {
            "search_type": "cnpj",
            "search_key": "00.000.000/0001-00",
            "response_type": "communication"
        }
    }'
    ```

    ```bash cURL (OAB)
    curl --location 'https://tracking.production.judit.io/tracking' \
    --header 'api-key: <API-KEY>' \
    --header 'Content-Type: application/json' \
    --data '{
        "recurrence": 1,
        "search": {
            "search_type": "oab",
            "search_key": "SP123456",
            "response_type": "communication"
        }
    }'
    ```

    </CodeGroup>

    <Note>
      The tracking will run for the first time within the next 24 hours after creation, in the best available processing window. From then on, it will run daily according to the `recurrence` field.
    </Note>

    Creation response:

    ```json
    {
      "tracking_id": "a94db796-9e35-4d0c-8e05-2a6b60f32a74",
      "user_id": "00000000-0000-0000-0000-000000000000",
      "status": "created",
      "recurrence": 1,
      "search": {
        "search_type": "name",
        "search_key": "EXAMPLE NAME",
        "response_type": "communication"
      },
      "hour_range": 4,
      "tracked_items_count": 0,
      "tracked_items_steps_count": 0,
      "tags": {},
      "created_at": "2026-05-20T04:52:50.223Z",
      "updated_at": "2026-05-20T04:52:50.223Z"
    }
    ```

    <Note>
      The `hour_range` field indicates the time at which processing will occur for the first time. In the example above, it is scheduled for 4 AM.
    </Note>

  </Step>
  <Step title="Checking the tracking status" stepNumber="2">
    The URL takes the **tracking_id** returned in the first request:

    ```bash
    curl --request GET \
    --url "https://tracking.production.judit.io/tracking/a94db796-9e35-4d0c-8e05-2a6b60f32a74" \
    --header "api-key: YOUR-API-KEY" \
    --header "Content-Type: application/json"
    ```

    Response:

    ```json
    {
      "tracking_id": "a94db796-9e35-4d0c-8e05-2a6b60f32a74",
      "user_id": "00000000-0000-0000-0000-000000000000",
      "status": "updated",
      "recurrence": 1,
      "search": {
        "search_type": "name",
        "search_key": "EXAMPLE NAME",
        "response_type": "communication"
      },
      "tracked_items_count": 3,
      "tracked_items_steps_count": 0,
      "tags": {
        "dashboard_id": null
      },
      "request_id": "186e0ed5-4656-4fd8-8e07-76f755c44a9d",
      "created_at": "2026-05-20T04:52:50.223Z",
      "updated_at": "2026-05-20T20:12:47.839Z"
    }
    ```

    The `status` property indicates the current state of the tracking, which can be:

    <ol type="a">
      <li><strong>created</strong>: Tracking created, but never executed.</li>
      <li><strong>updating</strong>: Has a request currently being processed.</li>
      <li><strong>updated</strong>: Tracking updated with at least one response available. The <u>updated_at</u> field shows the last update date and <u>request_id</u> the ID of the last execution.</li>
      <li><strong>paused</strong>: Tracking paused, but can still be resumed.</li>
      <li><strong>deleted</strong>: Tracking canceled and can no longer be resumed.</li>
    </ol>

    The **request_id** property is only populated after the tracking has executed at least once (status `updated`).
  </Step>

  <Step title="Retrieving the history of a tracking" stepNumber="4">
    To retrieve the history of publications found by a specific tracking, make a GET request to the `/responses/tracking/{tracking_id}` route:

    You can filter the results using the `created_at_gte` and `created_at_lte` parameters:

    - `created_at_gte`: defines the start date of the query;
    - `created_at_lte`: defines the end date of the query.

    ```bash

    --header 'api-key: <API-KEY>'
    ```

    ```bash
    -H "api-key: YOUR-API-KEY"
    ```
