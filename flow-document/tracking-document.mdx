title: "Monitoramento de Documento"
description: "Essa página tem como objetivo mostrar o fluxo de Monitoramento de novas ações por documento."
icon: "file"
---

<Steps>
  <Step title="Criação do monitoramento" stepNumber="1">
   ```bash
   curl --request POST
   --url "https://tracking.prod.judit.io/tracking"
   --header "api_key: SUA-API-KEY"
   --header "Content-Type: application/json"
   --data "{
     'recurrence': 1,
     'search': {
      'search_type': 'cpf',
      'search_key': '999.999.999-99'
     }
   }"
   ```

   <Note>
    Todas os monitoramentos de novas ações processuais cadastradas são realizadas ***on-demand***. Recomendamos verificar as condições de custo associadas a este serviço antes de sua utilização.
   </Note>

   Retorno:
   ```json
   {
   "tracking_id": "15d632c6-a2ab-40c1-bfc5-d8f7bf8d8dd9",
   "user_id": "82082593-c664-4d7b-b174-2f0dc4791daf",
   "status": "created",
   "recurrence": 1,
   "search": {
     "search_type": "cpf",
     "search_key": "092.065.297-22",
     "response_type": "lawsuits",
     "search_params": {
       "filter": {},
       "pagination": {}
     }
   },
   "tracked_items_count": 0,
   "tracked_items_steps_count": 0,
   "tags": {},
   "created_at": "2024-02-21T18:26:38.499Z",
   "updated_at": "2024-02-21T18:26:38.499Z"
   }
   ```

  O monitoramento irá ser iniciado a primeira vez, na melhor janela de
  concorrência de requisição ao tribunal, dentro das próximas 5 horas
  da data de criação.

  Depois ocorrerá de acordo com a frequeência cadastrada no campo ***recurrence***.

  <br />
  Filtros podem ser adicionados na requisição. Os filtros disponíveis podem ser encontrados na página:

  <a href="https://docs.judit.io/api-reference/endpoint/tracking/create">
  https://docs.judit.io/api-reference/endpoint/tracking/create
  </a>
  </Step>
  <Step title="Consultar o status do monitoramento" stepNumber="2">
  Na URL vai o <strong>tracking_id</strong> retornado na primeira requisição:

   ```bash
   curl --request GET
   --url "https://tracking.prod.judit.io/tracking/15d632c6-a2ab-40c1-bfc5-d8f7bf8d8dd9"
   --header "api_key: SUA-API-KEY"
   --header "Content-Type: application/json"
   ```

   Retorno:
   ```json
   {
    "tracking_id": "15d632c6-a2ab-40c1-bfc5-d8f7bf8d8dd9",
    "user_id": "82082593-c664-4d7b-b174-2f0dc4791daf",
    "status": "created",
    "recurrence": 1,
    "search": {
      "search_type": "cpf",
      "search_key": "092.065.297-22",
      "response_type": "lawsuits",
      "search_params": {
        "filter": {},

    },
    "tracked_items_count": 0,
    "tracked_items_steps_count": 0,
    "tags": {
      "dashboard_id": null
    },
    "request_id": "05ee9825-b2b4-480b-b29e-f071ca7d9c72",
    "created_at": "2024-02-21T18:26:38.499Z",
    "updated_at": "2024-02-21T18:26:38.499Z"
  }
   ```

   A propriedade status informa a situação atual do monitoramento,
podendo ser:

 <ol type="a">
   <li>
    <strong>created</strong>: Monitoramento criado, porém nunca executado.
   </li>
   <li>
    <strong>updating</strong>: Está com uma requisição em processamento.
   </li>
   <li>
   <strong>updated</strong>: Monitoramento atualizado já com alguma resposta
   disponível. O campo <u>updated_at</u> pode informar a data de última
   atualização do monitoramento e a propriedade <u>request_id</u> o id
   da última request feita pelo monitoramento.
   </li>
   <li>
    <strong>paused</strong>: Monitoramento pausado, podendo ainda ser reativado.
   </li>
   <li>
    <strong>deleted</strong>: Monitoramento cancelado e não pode mais ser
  reativado.
   </li>
 </ol>

 A propriedade <strong>request_id</strong> só é criada a partir da primeira vez que o
monitoramento executou, ou seja, chegou ao status updated.
  </Step>
  <Step title="Consultar o conteúdo da resposta (nova ação encontrada)" stepNumber="3">
  Na URL vai o <strong>request_id</strong> retornado na primeira requisição:

   ```bash
   curl --request GET
   --url "https://requests.prod.judit.io/responses/?request_id=15d632c6-a2ab-40c1-bfc5-d8f7bf8d8dd9"
   --header "api_key: SUA-API-KEY"
   --header "Content-Type: application/json"
   ```

      O parâmetro <strong>page</strong> e <strong>page_size</strong> são opcionais, porém necessários para
    percorrer as páginas com os processos, caso venham mais de uma, o
    que é comum no caso de consulta por documento.

    <Accordion title="As propriedades de paginação:" defaultOpen>
        <ParamField body="page" name="page" type="integer" required={false}>
            Define a página atual da busca.
        </ParamField>
        <ParamField body="page_count" name="page_count" type="integer" required={false}>
            Total de processos na página.
        </ParamField>
        <ParamField body="all_count" name="all_count" type="integer" required={false}>
            Total de processos encontrados
        </ParamField>
        <ParamField body="all_pages_count" name="all_pages_count" type="integer" required={false}>
            Quantidade de páginas de processos
        </ParamField>
        <ParamField body="page_data" name="page_data" type="array" required={false}>
            Array com as respostas e dentro da propriedade response_data o conteúdo do processo.
        </ParamField>
    </Accordion>

    <Note>
    No caso de monitoramento de documento, ele sempre será de novas
    ações, ou seja, as requisições só gerarão respostas caso um novo
    processo seja distribuído.
    </Note>
    O significado de cada campo pode ser encontrado no glossário:

    https://docs.judit.io/essentials/glossary
    </a>
