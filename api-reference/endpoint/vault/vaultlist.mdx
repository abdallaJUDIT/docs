<Accordion title="Tipos de Status das Credenciais">
*credential_status pode ser*:

`not exists`: Não cadastrada

`active`: Cadastrada e ativa

`inactive`: A credencial falhou no login do tribunal (senha inválida ou expirada, usuário bloqueado ou certificado vencido). Revalide o login no portal do tribunal e cadastre a credencial novamente para voltar a `active`.

Caso seja utilizado um cadastro no sistema \* (cadastro genérico), essa credencial será utilizada para todos os tribunais que não tenham outro cadastro na mesma `customer_key`, então cuidado com esse tipo de cadastro.

</Accordion>

Sem o parâmetro `customer_key` (ou com `?customer_key=*`), a resposta lista todos os sistemas disponíveis no Cofre, com o status de cada um na chave padrão `*` (use essa lista para copiar o `system_name` exato). O exemplo acima está resumido. Como ler o exemplo sem `customer_key`:

- **Linha `"name": "*"` com `"customer_key": ""`:** é a credencial coringa da chave padrão. O `customer_key` vem vazio porque não há coringa cadastrada nessa chave (`not exists`). Quando há, ele vem preenchido.
- **Demais linhas com `"customer_key": "*"`:** a API repete a chave padrão usada no filtro, mesmo quando o status é `not exists`. Esse `*` não é uma credencial coringa cadastrada.

Com `?customer_key=...`, a linha `"name": "*"` é a coringa dessa chave e as demais linhas são apenas os sistemas com credencial própria nela. Se nenhuma `customer_key` for informada no cadastro, é usado o valor padrão `*`; a chave padrão nunca é vazia.
