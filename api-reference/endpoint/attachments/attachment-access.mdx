O anexo é baixado a partir da **resposta** (`response_id`) que contém o processo. A rota retorna o campo `attachment_url`, com o link para download do arquivo.

Para que o anexo esteja disponível:

1. Crie a requisição com `"with_attachments": true`.
2. Busque as respostas em `GET /responses?request_id=<request_id>` e pegue o `response_id` do processo.
3. No array `attachments` do processo, use o `attachment_id` de um anexo com `status: "done"`.

<Note>
Precisa de todos os anexos do processo em um único arquivo? Veja [Baixar anexos consolidados](/api-reference/endpoint/attachments/attachment-consolidated).
</Note>

## Erros

| HTTP | `error.name` | `error.message` | Quando ocorre |
| :--- | :--- | :--- | :--- |
| `401` | `HttpUnauthorizedError` | `UNAUTHORIZED` | Header `api-key` ausente ou com chave inválida. |
| `403` | `HttpForbiddenError` | `FORBIDDEN` | A chave é válida, mas não tem permissão para acessar o recurso. |
| `404` | `HttpNotFoundError` | `NOT_FOUND` | O `attachment_id` não foi encontrado na resposta informada (`error.data`: `ATTACHMENT_NOT_FOUND_IN_RESPONSE`). |
| `500` | `HttpInternalServerError` | `INTERNAL_SERVER_ERROR` | Erro interno da Judit. Tente novamente e, se persistir, fale com o atendimento em [atendimento@judit.io](mailto:atendimento@judit.io). |

Todo erro usa o mesmo envelope. O código específico vem em `error.data`. Exemplo de `404` quando o anexo não está na resposta:

```json
{
  "error": {
    "name": "HttpNotFoundError",
    "message": "NOT_FOUND",
    "data": "ATTACHMENT_NOT_FOUND_IN_RESPONSE"
  }
}
```

Veja a lista de códigos de `error.data` em [Erros da API](/resource/errors).
