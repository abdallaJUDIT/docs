O anexo é baixado a partir da **resposta** (`response_id`) que contém o processo.

Para que o anexo esteja disponível:

1. Crie a requisição com `"with_attachments": true`.
2. Busque as respostas em `GET /responses?request_id=<request_id>` e pegue o `response_id` do processo.
3. No array `attachments` do processo, use o `attachment_id` de um anexo com `status: "done"`.

<Warning>
O download só funciona para respostas criadas há **até 30 dias**. Depois disso, a rota retorna `422` com `RESPONSE_ATTACHMENT_ACCESS_EXPIRED`. Para baixar o anexo, faça uma nova requisição para o processo.
</Warning>

## Resposta

A rota retorna **`200`** com o **próprio arquivo do anexo**, no formato original capturado do tribunal (PDF, HTML, imagem etc.). O `Content-Type` da resposta indica o formato (por exemplo, `application/pdf` ou `text/html`).

<Info>
A entrega é feita por redirecionamento para uma URL temporária do arquivo. Navegadores, Bruno, Postman e `curl --location` seguem o redirecionamento sozinhos. Se o seu cliente HTTP não seguir redirecionamentos, você recebe um `302` com a URL do arquivo no header `Location`.
</Info>

```bash cURL
curl --location 'https://requests.production.judit.io/responses/<response_id>/attachments/<attachment_id>' \
--header 'api-key: <api-key>' \
--output anexo
```

<Note>
Precisa de todos os anexos do processo em um único arquivo? Veja [Baixar anexos consolidados](/api-reference/endpoint/attachments/attachment-consolidated).
</Note>

## Erros

Todo erro usa o mesmo envelope. O código específico vem em `error.data`:

```json
{
  "error": {
    "name": "HttpNotFoundError",
    "message": "NOT_FOUND",
    "data": "ATTACHMENT_NOT_FOUND_IN_RESPONSE"
  }
}
```

| HTTP | `error.data` | Quando ocorre |
| :--- | :--- | :--- |
| `401` | `MISSING_AUTHORIZATION` | O header `api-key` não foi enviado. |
| `404` | `RESPONSE_NOT_FOUND` | O `response_id` não foi encontrado. |
| `404` | `ATTACHMENT_NOT_FOUND_IN_RESPONSE` | O `attachment_id` não está no array `attachments` da resposta. |
| `404` | `ATTACHMENT_NOT_FOUND` | O anexo está na resposta, mas o arquivo ainda não foi capturado (por exemplo, anexo com `status: "pending"`). |
| `422` | `RESPONSE_ATTACHMENT_ACCESS_EXPIRED` | A resposta foi criada há mais de 30 dias. Faça uma nova requisição para o processo. |
| `422` | `REQUEST_WITHOUT_ATTACHMENTS` | A requisição de origem foi feita sem `"with_attachments": true`. |

Os campos `error.name` e `error.message` seguem o status: `HttpUnauthorizedError` / `UNAUTHORIZED` (401), `HttpNotFoundError` / `NOT_FOUND` (404) e `HttpUnprocessableEntityError` / `UNPROCESSABLE_ENTITY` (422). Em `RESPONSE_ATTACHMENT_ACCESS_EXPIRED`, o `error.message` traz a orientação `Create a new request to the lawsuit to access the attachment`.

Veja mais sobre o formato dos erros em [Códigos de Erro](/resource/errors).
