A **Consulta Síncrona Tem Processo?** retorna, em milissegundos, um booleano indicando se um CPF, CNPJ, OAB ou Nome tem **algum processo** no datalake da Judit. É o caminho mais leve e barato para gates binários — KYC, qualificação de leads, alertas e roteamento.

> 🤖 Endpoint: `POST https://lawsuits.production.judit.io/lawsuits` com `pagination.page_size: 1`. A resposta inclui o booleano `has_lawsuits` no topo. Para minimizar payload e custo, use `page_size: 1` — o objetivo aqui é só saber **se existe**, não trazer a lista completa.

<EndpointBadges auth billing="billable" flow="sync" />

## Quando usar

<CardGroup cols={2}>
  <Card title="Gate de KYC" icon="shield-halved">
    Em onboarding, decida se vale executar uma diligência completa apenas quando `has_lawsuits = true`.
  </Card>
  <Card title="Qualificação de leads" icon="filter">
    Marque automaticamente leads como "com risco jurídico" antes de aprofundar a análise.
  </Card>
  <Card title="Roteamento e alertas" icon="route">
    Direcione para fluxos específicos (mesa de risco, compliance avançado) somente quem tem processo.
  </Card>
  <Card title="Telas de status" icon="bolt">
    Pinte um badge "tem processo / sem processo" em CRM/ERP sem trazer a lista completa.
  </Card>
</CardGroup>

<Note>
Para receber também a **quantidade** de processos, use [`POST /lawsuits/count`](/cache-judit/count). Para receber a lista completa de processos, use [`POST /lawsuits` (Hot Storage)](/cache-judit/hotstorage).
</Note>

## Passo 1: Criar a Consulta (POST)

`POST https://lawsuits.production.judit.io/lawsuits`

### Parâmetros do payload

| Parâmetro | Tipo | Obrigatório | Descrição |
| :--- | :--- | :--- | :--- |
| `search.search_type` | string | **Sim** | `cpf`, `cnpj`, `oab`, `name` ou `rji`. |
| `search.search_key` | string | **Sim** | Documento ou nome a ser consultado. |
| `search.response_type` | string | **Sim** | Use `"lawsuits"` para essa rota. |
| `search_params.pagination.page_size` | number | Recomendado | Use `1` para minimizar tráfego — só queremos `has_lawsuits`. |
| `search_params.filter` | object | Não | Os mesmos filtros do [Hot Storage](/cache-judit/hotstorage) (lado, tribunais, datas, valor, classes, assuntos, etc.). |

## Passo 2: Ler a resposta

A resposta é um JSON síncrono. O campo importante para esse caso de uso é `has_lawsuits`.

```json Resposta
{
    "has_lawsuits": true,
    "request_id": "87d9f7bf-0071-41ee-a721-e6e1b4082bc9",
    "lawsuits": [
        {
            "code": "0000000-00.0000.0.00.0000",
            "...": "..."
        }
    ]
}
```

| Campo | Tipo | Descrição |
| :--- | :--- | :--- |
| `has_lawsuits` | boolean | `true` se há ao menos um processo no datalake; `false` caso contrário. |
| `request_id` | string | UUID da consulta — útil para auditoria. |
| `lawsuits` | array | Lista de processos (vazia ou com 1 item, se `page_size: 1`). |

<Note>
Se você quer **somente** o booleano e nem precisa do array `lawsuits`, ainda assim recomendamos `page_size: 1` (a API sempre retorna a estrutura completa, mas com array minimizado). Para apenas a contagem (ex.: "tem 12 processos"), use [`POST /lawsuits/count`](/cache-judit/count).
</Note>

## Padrões e dicas

<AccordionGroup>
  <Accordion title="Combine com filtros para gates contextuais">
    Quer saber se a pessoa tem processo **trabalhista ativo no polo passivo nos últimos 5 anos**? Combine `tribunals.keys`, `side`, `distribution_date_gte`. Tudo em uma única chamada síncrona.
  </Accordion>

  <Accordion title="Tratamento de homônimos em consultas por nome">
    Buscas por `name` podem retornar resultados de homônimos. Para nomes comuns (ex.: "João da Silva"), confirme via CPF antes de bloquear o usuário. A Judit traz heurísticas (`possible_homonym`, `potential_homonym`) na lista — se você precisa só do booleano, complemente o gate com outra checagem documental.
  </Accordion>

  <Accordion title="Custo vs. lista completa">
    Esta rota é cobrada como uma consulta síncrona padrão. Se você já vai fazer uma consulta completa logo em seguida, pode pular este passo e usar diretamente o [Hot Storage](/cache-judit/hotstorage).
  </Accordion>

  <Accordion title="Cache (TTL)">
    O resultado pode ser cacheado pelo seu cliente conforme `cache_ttl_in_days`. Para fluxos críticos de KYC, considere TTL menor (1 dia) ou força refresh via [`POST /requests`](/requests/requests) com `on_demand: true`.
  </Accordion>
</AccordionGroup>
